# 关系反馈工具合并实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> 中文：执行者必须逐任务实施并用复选框跟踪；本项目按用户授权在当前会话内连续执行。

**Goal:** 完成爬山岛后，在世界地图提供可生成并缓存的破冰话术和游戏内个人说明书，并让个人说明书随正式剧情证据增加而按需更新。

**Architecture:** 前端把正式证据投影、固定变量映射、结果校验和按角色缓存放在环境无关的数据模块中，界面控制器只管理两个入口及互斥卡片。轻量同源服务端统一持有模型配置和网关客户端，两项业务服务各自校验请求、构造提示词、纠正一次模型结果，并返回固定结构。

**Tech Stack:** 原生浏览器模块、浏览器本地存储、原生 Node.js HTTP 与 Fetch、Vite 7、Node.js 内置测试运行器。

**Spec:** `docs/superpowers/specs/2026-08-23-关系反馈工具合并设计.md`

## Global Constraints

- 入口资格只认爬山岛 `firstCompletedAt` 与七组有效正式证据；重温状态不得隐藏入口。
- 模型调用只由点击触发；岛屿完成仅刷新按钮状态。
- 变量 1、2在爬山岛第 2、3 题为标准选项时必须使用设计文档中的固定九宫格。
- 破冰正文为 150～250 个中文码点的单段文字；个人说明书固定九变量、五章节。
- 后续剧情只使个人说明书缓存变旧，不使破冰缓存失效。
- 模型默认 `glm-5.3`，默认网关 `https://tokendance.space/gateway/v1/chat/completions`。
- 密钥只读取服务端 `TOKENDANCE_API_KEY`；浏览器、日志、构建产物和公开错误不得包含密钥。
- 不新增运行时依赖，不修改正式证据、首次完成时间、岛屿题目和解锁顺序。
- 个人说明书只在游戏卡片中展示，不提供 Word、PDF、下载和历史版本入口。
- 每个实现任务遵守先失败测试、再最小实现、再全量回归，并使用中文提交信息。
