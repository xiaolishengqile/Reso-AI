# 八岛连续剧情与画像系统实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将现有地图升级为雾谷入口、爬山岛、七座后续连续剧情岛和心愿岛组成的完整关系旅程，保存四十九组剧情证据并生成可解释的心仪对象画像。

**Architecture:** 保留现有爬山岛独立演出，新增一套供七座后续岛共用的剧情控制器、进度仓库和画布表现层；每座岛只保存自己的场景配置和画像信号。世界地图只管理十个位置与顺序解锁，画像模块只读取正式证据并生成结构化结果，心愿岛负责展示结果并为以后接入服务端人工智能保留单一异步接口。

**Tech Stack:** 原生 JavaScript 模块、HTML、CSS、Canvas、浏览器本地存储、Node 内置测试、Vite；不新增运行时依赖。

**Spec:** `docs/superpowers/specs/2026-08-23-七岛连续情侣冲突剧情与心仪对象画像设计.md`

## Global Constraints

- 爬山岛七组正式选择和后续七岛各六组正式选择，共四十九组剧情证据。
- 每道正式选择必须区分 `self`（用户行为）、`partner`（伴侣期待）或 `joint`（共同规则）。
- 每个选项必须有中性摘要、分类画像信号、局部反馈和同行者情绪，不使用诊断或贬义措辞。
- 选择反馈必须自然承接下一阶段，不能选完立即跳到无关问题。
- 首次完整游玩形成正式证据；重玩不得覆盖首次证据。
- 页面刷新后恢复当前岛和阶段；只有完成当前岛才解锁下一岛。
- 人工智能密钥不得放入浏览器。当前实现提供可运行的本地画像生成器和可注入的异步远程生成接口。
- 不新增运行时依赖；优先复用现有场景管理、角色绘制、地图移动和浏览器存储。
- 所有新增模块保持单一职责，单岛内容独立，不建立包含七岛全部文案的超大文件。
- 每项功能按测试驱动开发：先观察失败，再写最小实现，再运行相关测试和全量测试。
