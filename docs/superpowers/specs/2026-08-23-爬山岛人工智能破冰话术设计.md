# 爬山岛人工智能破冰话术设计

## 一、背景

当前爬山岛会在七组问题中记录用户的正式答案和结构化画像证据，完成后返回世界地图并解锁下一座岛。系统尚未在爬山岛完成后提供基于这些答案的即时反馈。

本次新增一个由用户主动触发的“破冰话术”功能：用户完成爬山岛后，世界地图右上角出现入口按钮；点击按钮后，服务端调用 `glm-5.3`，根据七组正式证据推演一个明确标注为虚拟的匹配对象，并生成一段 150～250 字、可以直接发送的破冰话术。话术使用附件模版的七段逻辑作为内容骨架，但最终呈现为一段自然、连贯的中文，而不是七段说明文字。

## 二、目标与边界

### 目标

1. 只有完成爬山岛且拥有七组有效正式证据时，世界地图右上角才显示“生成破冰话术”按钮。
2. 用户点击按钮后才发起生成，不在答题结束时自动调用模型。
3. 生成内容包含一个虚拟匹配对象昵称和一段 150～250 字的破冰话术。
4. 结果使用与现有世界地图一致的暖色、纸张和发光卡片风格展示。
5. 密钥仅存在于服务端环境变量，浏览器不保存、输出或接触密钥。
6. 请求失败、返回格式错误或模型暂时不可用时，答题证据、地图进度和已生成结果都不受影响。
7. 同一组正式答案只生成一次并保存在浏览器本地；再次点击按钮直接查看已有结果。

### 不在本次范围内

- 不接入真实用户匹配、聊天或好友系统。
- 不生成花束图片或人物图片。
- 不根据答案推断外貌、健康状况、心理疾病或其他敏感属性。
- 不修改七道问题、正式证据保护规则和后续岛屿解锁顺序。
- 不增加复制、分享、收藏、历史版本和主动重新生成能力。

## 三、方案选择

采用“同仓库轻量服务端”方案。开发环境由同一个服务同时承载现有页面和模型接口；生产环境由该服务提供构建后的静态文件和模型接口。实现优先使用运行时原生能力及项目已安装的构建工具，不增加第三方依赖。

未采用以下方案：

1. 浏览器直接请求模型网关：会把密钥打包到前端或暴露在网络请求中，不满足安全要求。
2. 特定平台的云函数：能够保证安全，但会把项目绑定到尚未确认的部署平台，当前没有必要。

## 四、模块职责

### 1. 世界地图破冰入口

新增独立的前端破冰功能模块，负责：

- 读取爬山岛完成状态和七组正式证据。
- 判断入口按钮是否显示。
- 管理卡片的关闭、加载、成功和失败状态。
- 调用站内破冰接口。
- 校验并缓存生成结果。

该模块不理解爬山剧情动画，也不修改爬山进度；`main.js` 只负责传入页面节点并初始化模块，避免继续扩大主入口文件职责。

世界地图游戏实例增加一个可选的“场景完成观察回调”。爬山场景完成、进度已保存且地图解锁状态更新后，由该回调通知破冰模块重新检查入口条件。这样入口能在当前页面内立即出现，不依赖刷新页面，也不使用定时轮询。

### 2. 破冰请求构造

前端只提交生成所需的最小数据：

- 协议版本。
- 七组证据的阶段标识、选项标识、选项文字、中性摘要、结构化信号、场景标签和压力等级。
- 用户昵称仅用于自然称呼，可缺省。

不提交完整本地存储、后续岛屿数据、角色精灵选择或无关个人资料。自由回答作为选项文字发送，但仍受现有 300 字上限和服务端整体请求大小限制。

### 3. 轻量服务端

服务端提供站内 `POST /api/icebreaker` 接口，并承担：

- 限制请求体大小，校验协议版本和七个唯一阶段。
- 从环境变量读取网关地址、模型名和密钥。
- 构造固定系统提示与用户证据摘要。
- 调用用户指定的聊天补全网关和 `glm-5.3`。
- 解析、清洗并校验虚拟昵称和话术。
- 将上游错误转换为不包含密钥、提示词和内部响应内容的安全错误。

同一服务在开发模式下挂载现有构建工具的中间件，在生产模式下提供 `dist` 静态文件。这样前端始终使用同源接口，不需要跨域配置，也不需要额外进程管理依赖。

### 4. 本地结果缓存

使用独立版本化存储项保存：

- 当前七组正式证据的答案签名。
- 虚拟匹配对象昵称。
- 破冰话术。
- 生成时间。

答案签名由固定阶段顺序下的阶段标识、选项标识和正式证据时间组成。缓存签名与当前正式证据一致时，按钮文案显示为“查看破冰话术”，点击后直接打开结果卡片；签名不一致、数据无效或存储解析失败时忽略旧缓存并重新生成。

## 五、生成内容规则

服务端提示词将附件模版转为以下七个内部写作节点：

1. 说明系统替用户过滤了不适合的相处方式，引出虚拟匹配对象。
2. 承认表层共同点，但把重点转向压力下的相容性。
3. 使用爬山、暴雨、计划受阻等与正式答案一致的危机场景。
4. 展示用户和虚拟对象可能发生的防御反应碰撞。
5. 说明虚拟对象如何通过价值排序和修复动作避开用户雷区。
6. 升华为安全感、被理解或被托底等关系价值。
7. 以自然、不施压的邀请收尾。

模型必须遵守以下边界：

- 虚拟昵称为简短中文昵称，不伪装成真实注册用户。
- 只根据传入证据组织表达，不编造用户未提供的具体人生经历。
- 不使用心理诊断、绝对人格判断和“命中注定”等保证性措辞。
- 最终话术是一个自然段，长度按 Unicode 字符计数为 150～250 字。
- 返回固定结构，只包含虚拟昵称和话术正文。

首次返回不满足固定结构、字段内容或长度要求时，服务端最多发起一次纠正请求；第二次仍不合格则返回生成失败，不把未经校验的内容交给前端。

## 六、界面与交互

### 世界地图入口

- 位置：世界地图右上角，与现有全岛、跳过和重置类控制保持安全间距。
- 未完成爬山岛：入口隐藏。
- 已完成且无有效缓存：显示“生成破冰话术”。
- 已完成且缓存有效：显示“查看破冰话术”。
- 请求进行中：按钮禁用，避免重复提交。

### 结果卡片

卡片采用现有系统的圆角、暖色半透明底、金色描边、柔和阴影和纸张质感，不引入新的视觉体系。卡片包含：

- “虚拟匹配对象”标识。
- 虚拟昵称。
- 150～250 字破冰话术。
- 关闭按钮。
- 失败状态下的简短错误说明和重试按钮。

卡片使用对话框语义，打开后焦点进入卡片，关闭后焦点返回右上角入口；状态变化通过可访问的实时区域播报。

## 七、数据流

1. 页面启动时加载爬山进度；任一场景完成后，世界地图通过观察回调通知破冰模块刷新状态。
2. 前端破冰模块检查最新完成状态和七组正式证据。
3. 条件满足时显示世界地图右上角入口，并检查本地缓存签名。
4. 用户点击入口；有有效缓存时直接展示卡片，没有缓存时进入加载状态。
5. 前端把最小化证据请求发送到站内接口。
6. 服务端校验请求、调用模型网关并校验结果。
7. 前端再次校验结果，保存带答案签名的缓存并展示卡片。
8. 任一环节失败时显示可重试状态，不修改爬山进度。

## 八、配置与安全

服务端使用以下环境变量：

- `TOKENDANCE_API_KEY`：必填，用户配置的网关密钥。
- `TOKENDANCE_API_URL`：可选，默认使用用户提供的聊天补全地址。
- `TOKENDANCE_MODEL`：可选，默认使用 `glm-5.3`。
- `PORT`：可选，服务监听端口。

仓库只提供不含真实密钥的示例配置文件。真实配置文件继续由忽略规则排除。服务端日志不输出请求授权头、自由回答全文或模型原始响应；对外错误只返回稳定错误码和中文提示。

## 九、异常处理

- 爬山完成但正式证据不足或损坏：隐藏入口，不发送请求。
- 密钥未配置：卡片提示“生成服务尚未配置”，允许配置后重试。
- 网络超时或网关异常：卡片提示暂时失败，保留重试入口。
- 模型返回空内容、非法结构或超出长度：服务端纠正一次，仍失败则拒绝结果。
- 本地缓存不可用：仍可完成本次生成和展示，只是不保证刷新后保留。
- 页面关闭或卡片关闭时请求仍在进行：忽略过期响应，避免关闭后重新打开卡片。

## 十、测试策略

### 前端单元测试

- 未完成爬山岛时入口隐藏。
- 完成但证据不足时入口隐藏。
- 七组证据完整时入口显示。
- 爬山场景完成观察回调会立即刷新入口，且不改变原有地图解锁行为。
- 有匹配签名缓存时直接展示，且不发起网络请求。
- 无缓存时正确进入加载、成功和失败状态。
- 连续点击不会重复请求，关闭后的过期响应不会覆盖界面。
- 无效服务端结果不会写入缓存。

### 服务端单元测试

- 请求体大小、协议版本、阶段数量和阶段唯一性校验。
- 提示词只包含允许的证据字段和固定安全约束。
- 正常解析网关返回并验证 150～250 字长度。
- 非成功状态、超时、空返回、非法结构和第二次校验失败的处理。
- 返回错误不包含密钥或上游原始内容。

### 集成验证

- 运行现有全部测试，保证岛屿进度和剧情流程不回归。
- 运行生产构建。
- 使用假的模型响应完成一次从右上角入口到结果卡片的浏览器流程。
- 在未配置密钥的环境验证安全失败提示。

## 十一、对现有流程的改变

原流程：完成爬山岛七组问题 → 返回世界地图 → 解锁后续岛屿。

新流程：完成爬山岛七组问题 → 返回世界地图并照常解锁后续岛屿 → 右上角额外出现破冰入口 → 用户按需生成或查看虚拟匹配对象的破冰话术。

因此，生成能力是一个不阻塞主旅程的附加反馈层：不改变答题时机、不延迟地图解锁、不覆盖正式证据，也不会因为模型不可用而阻止用户继续游玩。

## 十二、验收标准

1. 完成爬山岛前看不到入口，完成且证据完整后立即可见。
2. 点击入口才调用模型；刷新页面后仍可查看同一组答案对应的已生成结果。
3. 结果明确标记为虚拟匹配对象，话术为单段 150～250 字中文。
4. 卡片视觉与当前系统一致，并支持键盘关闭和焦点返回。
5. 浏览器代码、构建产物和网络响应中不存在服务端密钥。
6. 服务不可用时不影响爬山完成状态、正式证据和后续岛屿解锁。
7. 全部自动化测试和生产构建通过。
