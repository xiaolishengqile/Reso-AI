# 关系反馈工具合并设计

## 一、设计定位

本设计整合两项在爬山岛完成后开放的关系反馈功能：

1. **破冰话术**：根据爬山岛七组正式证据，生成一个明确标注为虚拟的匹配对象与一段可直接使用的破冰话术。
2. **个人说明书**：根据用户不断积累的正式剧情证据，生成并持续更新一份游戏内个人说明书。

本设计继承《爬山岛人工智能破冰话术设计》中未冲突的安全与生成约束；发生冲突时，以本设计为准。

本次交付必须真正实现两项功能。个人说明书只使用游戏内卡片展示，不生成或下载 Word、PDF 等文档。

## 二、目标

1. 用户首次完成爬山岛且拥有七组有效正式证据后，世界地图右上角显示关系反馈工具组。
2. 工具组包含相邻的“破冰话术”和“个人说明书”两个按钮。
3. 点击按钮才调用模型，不在完成岛屿时后台自动生成。
4. 个人说明书在爬山岛后形成初版；完成工作岛至未来岛中的任一岛后，进入可更新状态。
5. 更新只读取已保存的正式证据，不修改、覆盖或重新解释原始存档。
6. 模型不可用、返回错误或更新失败时，不影响游戏进度，并继续保留上一版有效结果。
7. 模型密钥只存在于服务端环境变量，浏览器、构建产物和错误响应不得包含密钥。
8. 同一角色、同一组证据对应的有效结果可以直接查看，不重复调用模型。

## 三、不在范围内

- 不接入真实用户匹配、聊天、好友或推荐系统。
- 不把虚拟匹配对象伪装成平台注册用户。
- 不生成图片、头像、花束或可下载文档。
- 不自动调用模型，不增加后台任务和轮询。
- 不修改首次正式证据保护规则。
- 不根据答案推断健康状况、心理疾病、种族、宗教等敏感属性。
- 不保存完整模型原始响应、授权头或服务端提示词。

## 四、界面与入口

### 4.1 关系反馈工具组

世界地图右上角新增独立工具组，避免继续扩大现有控制按钮的职责。

- 未完成爬山岛或七组证据不完整：整个工具组隐藏。
- 条件满足：同时显示“生成破冰话术”和“生成个人说明书”。
- 有与当前证据签名一致的缓存：按钮改为“查看破冰话术”或“查看个人说明书”。
- 个人说明书存在旧版但证据已增加：按钮改为“更新个人说明书”。
- 请求进行中：仅禁用对应按钮，不阻止地图和另一项工具使用。

两张结果卡片互斥打开，避免遮挡和焦点冲突。

### 4.2 破冰话术卡片

卡片包含：

- “虚拟匹配对象”标识。
- 二至十二字的虚拟昵称。
- 一段 150～250 字的中文破冰话术。
- 当前生成所依据的“爬山岛七组选择”说明。
- 关闭按钮；失败时显示简短错误和重试按钮。

### 4.3 个人说明书卡片

卡片包含：

- 标题“我的个人说明书”。
- 版本号，例如“第 4 版”。
- 已融合来源，例如“爬山岛、工作岛、吃饭岛、同居岛”。
- 九个核心变量的简要结论。
- 五个叙事章节。
- 每章的置信度和证据数量。
- “更新说明”，指出这一版新增了哪些岛屿证据。
- 关闭按钮；有新证据时提供“更新个人说明书”。

窄屏时工具按钮纵向排列，卡片使用单列布局并限制最大高度，正文区域可滚动。

## 五、个人说明书内容协议

### 5.1 九个变量

1. 危机应对本能。
2. 失控下的下意识反应。
3. 需要避开的互斥相处模式。
4. 不相容对象可能产生的误读。
5. 用户在该模式中的负面感受。
6. 最需要被尊重的关系红线。
7. 合适伴侣的包容或修复动作。
8. 能量恢复方式或核心情感需求。
9. 人生愿景与长期生活方向。

每个变量必须包含：

- 固定变量标识。
- 简短名称。
- 一至三句解释。
- 置信度：低、中、高。
- 一至十二条正式证据引用。

### 5.2 变量 1、2：防御本能

变量 1、2直接读取第 3 题 `slip` 的瞬时高压反应，并用第 2 题 `fatigue` 的压力沟通方式补充变量 2的表述。第 3 题决定核心方向，模型不得把它改成另一类反应。

| 第 3 题 | 变量 1核心方向 | 变量 2核心方向 |
|---|---|---|
| `command` | 危机中倾向用指令接管局面的行动者 | 通过明确指令恢复秩序和控制感 |
| `support` | 默默行动的实干者 | 少说多做，用实际行动提供可靠支点 |
| `freeze` | 高刺激下需要缓冲的敏感反应者 | 可能短暂停顿和信息过载，随后再进入行动 |

第 2 题只补充变量 2的起始方式：`solve` 为先拆解客观问题，`empathize` 为先确认感受，`blame` 为压力下可能先划分责任。展示不得使用“救世主情结、心理边界崩塌”等诊断或贬损标签。

### 5.3 变量 3～5：红牌禁区

变量 3、4、5基于第 2 题 `fatigue`、第 4 题 `storm-thought` 和第 6 题 `home-message` 识别用户的脆弱点，再描述需要避开的反向相处模式。规则按以下顺序匹配：

1. 第 6 题为 `anxious`：变量 3指向遇到危机时长期撤退并拒绝沟通；变量 4描述用户的高密度情绪确认可能被误读为压力；变量 5描述用户难以接受冷处理、断联和回避共同承担。
2. 上一条不适用且第 2 题为 `solve`：变量 3指向遇事先推卸责任、拒绝共同解决；变量 4描述事实和方案导向可能被误读为缺少温度；变量 5描述用户难以接受把现实责任留给伴侣的互动。
3. 前两条不适用且第 2 题为 `empathize`：变量 3指向把计划秩序置于人的安全与感受之上；变量 4描述共情优先可能被误读为犹豫或拖延；变量 5描述用户难以接受为目标忽视安全和伴侣主体性的做法。
4. 标准选项未命中前三条时，以第 4 题的危机价值排序和第 6 题的亲密距离信号进行中性组合，使用中置信度；自由回答则交由模型结合摘要生成，使用低置信度。

附件中的“疯子、拖油瓶、暴君、冷血”等攻击性文案只表达互斥方向，不得进入结果、提示词示例或缓存。

### 5.4 变量 6～8：修复补给

变量 6、7、8由第 5 题 `cave-repair` 的直接修复偏好和第 6 题的亲密距离需求共同决定。第 5 题优先，第 6 题用于补充：

- 第 5 题为 `space`，或第 5 题没有直接偏好且第 6 题为 `avoid`：变量 6是事后说教和高密度逼问；变量 7是提供热饮或实际照顾后退开半步；变量 8是不被打扰、尊重能量恢复节奏的缓冲空间。
- 第 5 题为 `hug`，或第 5 题没有直接偏好且第 6 题为 `anxious`：变量 6是低谷期冷处理和独自撤离；变量 7是稳定的拥抱、陪伴和“我在这里”的确认；变量 8是身体接触与言语肯定带来的连接感。
- 第 5 题为 `lecture` 且第 6 题为 `secure`：变量 6是只判定对错、不确认感受；变量 7是先确认安全与关系，再平等复盘；变量 8是既保持连接又不被否定的安全沟通。

当第 5 题与第 6 题信号冲突时，以更直接描述修复动作的第 5 题为准，不把用户固定成某种依恋类型。

### 5.5 变量 9：终极航向

变量 9直接读取第 7 题 `city-realization`：

- `build`：在城市扎根，建设能够提供稳定感的长期家园。
- `enjoy`：减少被遥远规划压抑，重视当下的热饭、拥抱和真实体验。
- `roam`：保持流动和探索，追求更远、更自由、没有固定剧本的人生。

未来岛完成后，变量 9保留上述初始方向，并用新的城市、事业、承诺、婚育和家庭照护证据更新置信度与具体表述。

爬山岛初版中，没有足够证据的变量必须标记为低置信度和“后续旅程将继续验证”，不得用绝对化标签填满模板。

### 5.6 五个叙事章节

1. 表层标签与深层关系需求。
2. 极限压力下的防御本能。
3. 冲突与需要避开的模式。
4. 合适的冲突修复与支持蓝图。
5. 人生愿景与关系方向。

章节只对九个变量进行可读叙述，不引入未在变量或证据中出现的新事实。

## 六、持续更新规则

个人说明书以“正式证据签名”判断是否需要更新。签名包含角色、证据版本、岛屿标识、阶段标识、选项标识和首次回答时间，并按固定顺序计算。

| 新完成岛屿 | 主要更新方向 |
|---|---|
| 工作岛 | 事业排序、工作边界、疲惫支持、沟通与异地规划 |
| 吃饭岛 | 日常照顾、共情、在场、责任承担与修复方式 |
| 同居岛 | 个人空间、作息、家务责任、能量恢复与共同生活边界 |
| 金钱岛 | 风险观、信任、控制、家庭金钱边界与责任公平 |
| 社交岛 | 社交能量、异性边界、公开关系、家庭立场与忠诚 |
| 旅行岛 | 压力反应、团队决策、可靠性、修复与共同学习 |
| 未来岛 | 城市、事业、承诺、婚育、父母照护与长期生活愿景 |

更新规则：

1. 岛屿完成时只刷新按钮状态，不自动请求模型。
2. 用户点击“更新个人说明书”后提交当前全部有效正式证据。
3. 服务端保留变量 1～9由爬山岛固定规则确定的核心方向，并用新证据修正置信度和具体表述。
4. 变量 9在未来岛完成后优先使用未来岛证据重新归纳。
5. 模型更新失败时继续显示上一版结果，并保留“更新”入口。
6. 只缓存最新版；显示版本号与已融合岛屿，不实现历史版本浏览。

## 七、数据与缓存

### 7.1 正式证据

现有雾谷、爬山岛和七座剧情岛存档继续作为唯一事实来源。生成模块只能读取，不得修改任何正式证据、首次完成时间和角色进度。

### 7.2 个人说明书缓存

使用独立版本化存储项，按角色隔离：

```json
{
  "version": 1,
  "players": {
    "girl": {
      "evidenceSignature": "manual-...",
      "revision": 4,
      "completedIslands": ["mountain", "office", "dining", "cohabitation"],
      "evidenceCount": 25,
      "variables": [],
      "sections": [],
      "updateSummary": "本版新增同居岛证据",
      "generatedAt": 0,
      "model": "glm-5.3"
    }
  }
}
```

缓存损坏时忽略旧数据，不影响游戏；保存失败时仍展示本次结果并提示刷新后可能无法保留。

### 7.3 破冰缓存

破冰话术继续使用独立存储项，并只以爬山岛七组正式证据签名判断有效性。后续岛屿完成不会使破冰缓存过期。

“重新开始游戏”必须同时清除两项结果缓存。

## 八、服务端与模型

### 8.1 同源服务

新增同仓库轻量服务端：

- 开发环境挂载现有构建工具中间件。
- 生产环境提供 `dist` 静态文件。
- 提供 `POST /api/icebreaker`。
- 提供 `POST /api/personal-manual`。
- 使用同一个模型网关客户端、超时控制和安全错误转换。

浏览器只请求本站接口，不直接访问模型网关。

### 8.2 环境配置

项目根目录提供不含密钥的 `.env.example`：

```dotenv
TOKENDANCE_API_KEY=
TOKENDANCE_API_URL=https://tokendance.space/gateway/v1/chat/completions
TOKENDANCE_MODEL=glm-5.3
PORT=5173
```

真实值写入被版本控制忽略的 `.env`。服务端启动时读取配置：

- `TOKENDANCE_API_KEY`：必填的模型网关密钥。
- `TOKENDANCE_API_URL`：可选的聊天补全地址。
- `TOKENDANCE_MODEL`：可选，默认 `glm-5.3`。
- `PORT`：可选，默认 `5173`。

破冰话术与个人说明书共用上述配置，不维护两套密钥或模型名。

### 8.3 请求最小化

个人说明书请求只包含：

- 协议版本和角色标识。
- 当前正式证据签名。
- 已完成岛屿列表。
- 允许使用的正式证据字段：岛屿、阶段、选项文字、中性摘要、结构化信号、上下文、压力等级和证据引用。
- 变量 1、2的固定映射结果（固定选项适用时）。
- 旅人昵称可选；不提交完整本地存储和无关界面状态。

服务端再次校验证据数量、岛屿阶段唯一性、文本长度和字段白名单。

### 8.4 模型返回与校验

破冰返回固定字段：虚拟昵称、单段话术。

个人说明书返回固定字段：九个变量、五个章节、更新摘要。服务端补充版本、证据签名、完成岛屿、生成时间和模型名，不信任模型填写这些元数据。

校验要求：

- 九个变量标识必须完整且不重复。
- 五个章节标题与顺序固定。
- 所有证据引用必须来自请求中的正式证据。
- 置信度只能为低、中、高。
- 不允许空内容、超长内容、诊断性措辞和保证性措辞。
- 不允许把虚拟对象描述为真实注册用户。
- 模型首次返回无效时最多纠正一次，第二次仍无效则拒绝结果。

## 九、安全措辞

附件中“独裁防御者”“彻底碎裂”“救世主情结”等内容只能作为需求语义参考，不得原样作为用户标签。展示层使用中性行为描述，例如：

- “危机时倾向强势接管局面”。
- “高刺激下可能出现信息过载”。
- “压力下会先通过控制感保护自己”。

系统不得进行心理诊断、把一次选择写成固定人格，或用“命中注定、完美契合、百分之百”等语言作出保证。

## 十、错误处理

- 未配置密钥：卡片提示“模型生成服务尚未配置”。
- 网络、超时或网关错误：提示暂时失败并允许重试。
- 请求证据损坏：拒绝请求，不覆盖缓存。
- 模型结构无效：纠正一次，仍无效则显示安全错误。
- 本地缓存损坏：忽略旧缓存并允许重新生成。
- 请求期间关闭卡片：忽略过期响应。
- 个人说明书更新失败：继续展示上一版。
- 一项工具失败：不影响另一项工具和世界地图。

错误响应只包含稳定错误码和中文公开提示，不包含密钥、堆栈、提示词、授权头、完整自由回答或上游原始响应。

## 十一、模块边界

建议新增以下独立模块，避免继续扩大主入口和爬山场景文件：

- `src/relationshipTools/`：右上角工具组与共享界面状态。
- `src/icebreaker/`：破冰请求、结果校验、缓存和卡片控制器。
- `src/personalManual/`：变量映射、请求、结果校验、证据签名、缓存和卡片控制器。
- `server/modelGateway.js`：共享模型网关请求、超时和响应提取。
- `server/icebreakerService.js`：破冰提示词与业务校验。
- `server/personalManualService.js`：个人说明书提示词、固定变量和业务校验。
- `server/app.js`：同源接口和静态文件服务。
- `server/index.js`：加载环境配置并启动服务。

`main.js` 只负责组合模块和传入页面节点。地图通过一个可选的场景完成观察回调通知工具组刷新资格，不理解模型和缓存细节。

## 十二、流程变化

原流程：

完成爬山岛 → 返回世界地图 → 继续后续岛屿。

新流程：

完成爬山岛 → 返回世界地图 → 右上角出现破冰话术与个人说明书入口 → 用户按需生成 → 继续完成后续岛屿 → 个人说明书显示可更新 → 用户按需生成新版。

模型功能是附加反馈层，不阻止地图解锁、剧情游玩或心愿岛画像生成。

## 十三、测试与验证

### 前端数据测试

- 爬山岛七组证据资格判断。
- 第 2、3 题九宫格全部组合。
- 自由回答不会被错误套用固定组合。
- 个人说明书请求只包含允许字段。
- 证据签名在新增正式证据后变化，重玩不覆盖时保持不变。
- 缓存按角色隔离、损坏安全回退、重新开始可清除。
- 九变量、五章节、证据引用和禁用措辞校验。

### 服务端测试

- 环境配置加载与密钥缺失处理。
- 请求方法、内容类型、体积、协议、阶段数量和字段白名单。
- 模型网关授权、模型名、超时和安全错误。
- 两种服务的正常解析、一次纠正和最终拒绝。
- 对外响应不泄露密钥、提示词和上游原文。

### 界面测试

- 未完成爬山时工具组隐藏，完成后无需刷新立即显示。
- 两个按钮相邻且状态独立。
- 缓存有效时直接查看，不发送请求。
- 新岛屿完成后个人说明书变为可更新，破冰缓存仍有效。
- 更新成功替换最新版，更新失败保留旧版。
- 连续点击不重复请求，关闭后过期响应不写回。
- 键盘焦点、实时状态、关闭后焦点返回和窄屏布局正确。

### 完整验证

- 全量自动化测试通过。
- 生产构建通过。
- 未配置密钥时两个入口均显示安全失败提示。
- 使用假的模型响应完成两条端到端浏览器流程。
- 视觉检查桌面与窄屏的工具组、加载、成功、失败和更新状态。
- 构建产物、前端源码和错误响应中不存在真实密钥。

## 十四、验收标准

1. 爬山岛完成后同时出现破冰话术和个人说明书按钮。
2. 破冰话术按原设计生成并缓存虚拟对象话术。
3. 个人说明书在爬山岛后可生成初版，且变量 1、2遵守九宫格映射。
4. 后续任一岛屿完成后，个人说明书在不自动调用模型的前提下显示可更新。
5. 更新版融合全部当前正式证据，展示版本、来源、变量、章节、置信度和更新说明。
6. 个人说明书只在游戏卡片中展示，没有文档导出入口。
7. 两项功能共用安全的服务端模型配置，真实密钥不接触浏览器。
8. 失败不修改进度、不覆盖正式证据、不丢失上一版有效结果。
9. 全部测试、构建、安全检查和桌面／窄屏视觉验证通过。
