# 爬山岛视频剧情重构设计

## 目标

将爬山岛从“程序绘制场景配文字旁白”改为“全屏视频或图片承载剧情、媒体结束后显示问题”的沉浸式流程。男女玩家使用同一套媒体素材；画像问题、选项和分析以《剧本(3)》为准。

## 已确认体验

1. 进入爬山剧情后，先显示一张符合主题的大山入口图片。
2. 玩家点击“开始旅程”后播放咖啡馆三段视频，三段连续播放且中间不出现文字旁白。
3. 每个视频剧情节点播放结束后停留在最后一帧，再显示问题和选项。
4. 问题面板固定在画面底部，视觉和交互参考雾谷入口的老人问答：深色半透明背景、浅色文字、双列选项，窄屏改为单列。
5. 用户选择后立即保存画像证据并进入下一段媒体，不展示额外旁白或文字反馈。
6. 缺少视频的“回家消息”和“城市顿悟”使用同画风全屏图片，图片出现后立即显示对应问题。
7. 男女玩家播放相同视频和图片，视频中的固定人物不随玩家性别替换。
8. 完成全部七组画像问题后显示完成按钮并返回世界地图。

## 剧情与画像规则

- 保留七个正式画像题：周末邀约、疲惫与抱怨、生死一瞬、暴雨抉择、避难与修复、回家消息、城市顿悟。
- 删除旧版单独的“暴雨行动”非画像节点；最新版剧本的四个暴雨念头直接进入避难与修复。
- 每个正式选项继续保存题目标识、选项目标识、检测维度、分析、同行者情绪与作答时间。
- 已完成剧情重温时保留首次正式证据，从入口图片重新开始播放。
- 刷新后恢复到已保存的当前题目，并从该题目的媒体开头重新播放。

## 组件边界

- `storyContent.js`：只保存剧情问题、选项、分析和跳转。
- `media.js`：只保存阶段到视频或图片素材的映射，并提供校验和查询函数。
- `createMountainScene.js`：负责入口、媒体播放、媒体结束、问题展示、选择保存和完成回调。
- `mountainScene.css`：负责全屏媒体和雾谷式底部问题面板。
- `index.html` 与 `main.js`：只声明并注入视频、图片、面板和按钮节点。

不新增第三方依赖。视频播放使用浏览器原生能力；图片使用项目静态资源。

## 播放失败与可访问性

- 视频自动播放失败时，显示“点击播放本段剧情”按钮，用户点击后继续。
- 视频加载失败时保留问题入口，显示简短错误提示，避免玩家被永久卡住。
- 视频元素提供简短无障碍说明；问题文本使用礼貌播报区域；所有按钮支持键盘焦点。
- 尊重减少动态效果偏好：不增加额外闪烁或面板动画，但剧情视频仍由用户主动开始。

## 验收标准

- 男女角色进入后看到同一大山入口图片。
- 视频播放期间问题面板不可见，最后一段媒体结束后问题准确出现。
- 咖啡馆三个视频连续播放，只在最后一段结束后显示第一个问题。
- 两个缺失视频阶段使用图片并立即显示问题。
- 全程不显示旧旁白、反馈文字或程序绘制人物。
- 七组答案均可保存，完成后仍能正确解锁后续进度。
- 桌面和窄屏下问题面板均不遮住主要媒体内容，且可以完整滚动。
